        ⚠ Three things worth fixing

        Found while tracing usage — none of these are what you asked for, but they're real and worth knowing about.

        1. A destructured model that's undefined at runtime, and it's now reachable. server/routes/referenceData.js:3 destructures BusinessCapability from models/ReferenceData.js — but that file's module.exports never defines it (only BusinessFlow, Product, Application, Actor, Channel, Domain, Subdomain, LineOfBusiness). Any request that hits the generic /:collection CRUD route with businessCapabilities calls .find() on undefined and throws. This router was previously never mounted — it got wired up in server/index.js during this session's earlier work on the application-lookup bug, so this path is live now where it wasn't before. server/scripts/seed-capabilities-full.js has the identical bug and would crash immediately if run.
        2. Three files register a Mongoose model literally named Actor. models/Actor.js, models/Persona.js, and models/ReferenceData.js all define one, and Mongoose's pluralization sends all three to the same actors collection. The guarded ones (mongoose.models.Actor ||) mean whichever is require'd first wins process-wide — currently models/Actor.js, since server/index.js loads it before ReferenceData.js. It works today by load-order accident, not by design.
        3. models/Persona.js is dead code. Nothing in the codebase ever require's it, so its (looser) Actor schema never registers and never runs.
